# 架构与文件保护

## 0.1.9 引用文本整理与统一设置

`plugin/content/text/` 的 options/protected/lineBreaks/whitespace/punctuation/index 提供不依赖 Zotero、DOM、Python 或网络的纯文本函数，沿用 0.1.8。`textUI.js` 连接复制与新高亮保存；`textPreferences.js` 只保存本地文本偏好，不配置或启动 OCR 后台。

`text/annotations.js` 监听 item/add，校验通知 instanceID 属于当前 PDF Reader、父附件、可编辑高亮/下划线且非外部注释，再修改 annotationText 并 saveTx。插件自己的 modify 不携带原 Reader instanceID，确保原生 Reader 收到更新。只处理新建事件，不扫描历史、不响应之后的手工修改，不依赖 OCR 任务/回执。保存失败回退缓存值，重复事件防重入，退出时注销并等候在途保存。没有副本字段或恢复开关。

旧的 `text/sidebar.js` 已移除，不改写或隐藏阅读器 DOM。数据库结构不变，仅通过宿主 API 保存用户已要求修改的注释字段；PDF/MD/JSON 文件链不变。

`preferences.xhtml` + `preferences.css` + `preferences.js` 统一两级导航、卡片与主题颜色。三个大类、八个子页；引用设置与 OCR 设置分别保存。所有字段保留原配置 key。OCR 设置全量验证后才落盘，错误跳转到对应子页；删除令牌与清缓存由用户确认，预览/文本保存不启动后台。

## 方案选择

Zotero 负责菜单、匹配、设置、进度、关闭并重新打开阅读器、结果附件和同步/全文索引。纯 Python 后台服务负责官方 HTTP 请求、持久化队列、结果解析、PDF 生成和文件替换。

选择直接官方 API：协议有官方源码可核对，不需要把 Codex MCP 会话转交给 Zotero，也不依赖在 Gecko 中运行 Node.js SDK。MCP 适合由已有 MCP 主机编排，本插件没有实现额外 MCP 客户端，以减少配置和维护面。

选择独立辅助进程处理 PDF：PyMuPDF 提供成熟的 PDF 对象和 Unicode 字体接口，无法直接作为 Zotero 内部 JS 库运行。已安装的 Python 用于创建独立环境，依赖只装一次。进程按需启动、跨文献复用，空闲且无任务 15 分钟后退出。

启动层同时覆盖 Windows 与 macOS。Windows 从注册表和 `PATH` 查找 Python；macOS 除 `PATH` 外，还显式检查 Homebrew、python.org Framework、MacPorts、Conda/Miniforge、pyenv、asdf 等常见位置，避免 Finder 启动的 Zotero 因环境变量精简而找不到解释器。设置中的 `~/...` 在 macOS 上按当前用户目录展开。XPI 只分发 Python 源码，不分发平台可执行文件；隔离环境中的 Python 和 PyMuPDF wheel 由目标机器按自身架构安装。

## 队列和恢复

同时处理的 PDF 数、同一 PDF 的并行段数均可设 1–2。全进程共享两段信号量，分段工作线程与 PDF 队列线程分离，避免相互占满工作池。任一页段异常会阻止本 PDF 的后续提交，已返回回执持续保存。MuPDF 操作通过共享锁串行，避免在多个 Python 线程中同时调用 MuPDF。HTTP 客户端和中文字体资源在进程内复用。后台服务使用 Windows `msvcrt` 或 POSIX `fcntl` 文件锁，确保同一 Zotero 配置目录只有一个任务进程接管队列。

每份任务有独立的原始输入快照、任务 JSON、结果和候选 PDF。记录 SHA-256、模型、参数、提交时间、页数、页段、批次和官方任务 ID。原始结果未被日志清理删除。相同源文件、模型、参数和服务地址使用相同缓存键；不同附件内容相同时也复用完成结果和不确定的提交回执。

提交前持久化意图；提交响应丢失时只查原批次。取消后保留回执，恢复不产生新 POST。正常关闭与用户取消分别记录：关闭时的任务下次自动恢复，用户取消的任务等待显式恢复。

API 计时包含提交、轮询、结果下载；本地 PDF 生成时间单独记录。不会把本地页数记录解释成账户实时剩余额度。

## 收纳和可观察进度

独立存档在同一文献库创建普通 `document` 条目，加入“PDF Repair 识别存档”集合，用 `extra` 中的 `PDFRepair-Source: <PDF附件key>` 精确标识所属 PDF，并与原文献建立双向关联。附件 key 随 Zotero 同步保持，可在另一设备重新发现存档。创建在 Zotero 事务中完成；收纳按 PDF 串行，使用哈希匹配现有 MD/JSON，变更 parentID 而非删除重建附件。

插件本地隐藏方式直接保留任务目录内结果，不创建库内附件。旧的同级导入和链接方式继续可选。收纳结果单独记入附件回执，已完成任务改变收纳位置不改变 OCR 参数或触发重新生成。来源文件未下载时阻止自动切换为 OCR。

PDF 引擎逐页报告写入、校验完成数；内存状态随页更新，进度日志最多约每秒写一次，阶段改变和阶段完成另行落盘。云端轮询读取真实 `extractProgress`，将各段已解析页数合计，同时单列已下载结果页数；缺失或异常进度不估算。状态表显示每段当前阶段、累计耗时和最后成功查询时间。文件保存、替换和索引使用等待状态。识别 100% 不代表 PDF 已完成，最终完成状态以 Zotero 回执为准。

## PDF 写入

打开原 PDF，对已有页面追加文字对象，使用文本渲染模式 `3`。嵌入 Droid Sans Fallback Unicode 字体，由 MuPDF 写出相应文本资源和 ToUnicode 映射。原页面图像不重采样，不按 Markdown 重新排版。

页面坐标以裁剪页为基准，按 OCR 尺寸缩放，并使用页面逆旋转矩阵转换。多边形提供行方向和倾斜。保留页面数量、尺寸、元数据和 PDF 内原有批注。

默认验证仅检查输出存在、非空、PDF 结构可解析、页数一致、追加不可见文字指令且可提取文字。开发测试中的逐页渲染比较不在运行路径内。

## 安全替换

候选 PDF 位于任务目录，生成和检查通过前不写原路径。替换前校验候选文件哈希，校验当前 PDF 仍是任务提交时的版本，创建并校验内容寻址的原始备份。

候选文件复制到原 PDF 所在目录的临时文件并同步落盘，再进行同目录原子替换，支持任务目录和 Zotero 附件目录位于不同卷。替换失败时原文件保留；Windows 文件锁或 macOS 权限/同步冲突会报错并允许重试。

插件没有删除重建 PDF 附件。条目 ID、key、父文献和 Zotero 批注关联保留，文件变化后标记待同步并刷新全文索引。如果阅读器打开，先保存阅读状态并关闭，完成后重新打开。

恢复前校验备份和当前文件。如果当前 PDF 不匹配已知生成版本，拒绝覆盖外部修改。备份按内容去重；中间任务快照和识别结果为便于恢复而保留，不自动批量删除。

备份和替换依赖本地文件系统的重命名语义；不承诺任意网络共享、同步盘冲突或突然断电时的数据库级跨系统事务。任务记录可以识别已经替换但尚未更新 Zotero 的状态，并在重启后补全元数据。
