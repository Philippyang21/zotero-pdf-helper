# 0.1.7 更新说明

发布日期：2026-10-21。基于 0.1.6 圆形图标版；Windows x64 与 macOS 使用同一个 XPI，仍需要 Python。

这次更新解决大文件一段一段等待、看不到真实云端页数和难以判断卡在哪个环节的问题：

- 云端返回逐页进度时，显示真实页数和识别百分比；区分已解析与已下载，不把识别完成当成 PDF 保存完成。
- 分别显示每段上传、排队、解析、下载状态和最近查询时间。
- 超限文件根据实际大小切成尽量接近 48 MB 的连续页段，替代反复对半切分；不压缩扫描图，不降低清晰度。
- 同一 PDF 默认最多同时处理两段，所有 PDF 总计最多同时处理两段；可在设置中改为单段。
- 记录各阶段累计耗时与云端流程用时，便于区分上传慢、排队长和识别慢。时间按客户端观察统计；并行时间会重叠。
- 继续保留原任务 ID、批次和已下载结果；提交回执不明时先查原批次，未查到唯一任务则暂停等待确认。
- 升级保留旧页段与已提交任务。旧任务之前的阶段耗时不会猜补，新的分段算法用于新任务。

安装：Zotero → 工具 → 插件 → 齿轮 → 从文件安装插件，选择 `zotero-paddleocr-pdf-repair-0.1.7.xpi`。完全退出并重启 Zotero后，在任务窗口查看原任务；暂停时点一次“恢复 / 重试”。无需删除旧插件、任务目录、Token 或 Python 环境。

这次更新改善插件调度与可观察进度。云端排队和识别速度由官方服务及文档内容决定，不能承诺固定倍数的提速。新增并行流程已通过离线模拟接口与本地服务测试；没有通过上传用户文献来消耗额度测试，也尚未在目标 Mac 上安装实测。
