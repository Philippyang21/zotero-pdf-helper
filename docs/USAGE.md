# 安装与使用说明（Windows x64 / macOS）

## 0.1.13 候选：PDF OCR Helper 与检查更新

本地候选已更名为 PDF OCR Helper，采用新的羊驼图标，支持 Zotero 7、8、9 与 10.0.x。Windows x64 已验证 7.0.32、8.0.4、9.0.6、10.0.6，macOS 仍待原生验收。旧版用户覆盖安装 pdf-helper-0.1.13.xpi，原插件 ID、设置、令牌及任务目录继续沿用。设置 → PDF OCR Helper → 高级与维护 → 检查更新，点击才查询；适用新版显示版本说明，经“前往中文社区下载”确认后打开本插件详情页，取消留在设置。下载 .xpi 后在工具 → 插件中从文件覆盖安装，并按提示重启。不卸载原插件。

当前仓库、真实详情页及更新源尚未配置，点击会显示“检查更新尚未配置”，并非网络已接通或当前已是最新版本。不兼容的新版本只提示要求，不推荐下载。未配置或检查失败不影响 OCR、PDF 和文本整理。此功能不用 Python、不上传文献/令牌、不自动下载或安装。发布者配置步骤见 [发布指南](RELEASING.md)。

Zotero 10 安装要求保留原 manifest 的 HTTPS update_url 占位；宿主自带更新检查可能尝试该预留域名。本次不修改宿主全局设置，也没有部署原生自动更新源。

## 这个插件做什么

很多扫描版 PDF 看起来正常，但里面只有图片，不能搜索和复制文字。这个插件可以调用 PaddleOCR 云端识别，也可以直接使用你已有的 MD 和 JSON，在原 PDF 上添加一层看不见的文字。

处理完成后，PDF 的页面外观、页数以及 Zotero 附件位置保持不变，同时可以在 Zotero 中搜索和复制文字。替换前，插件会自动备份原 PDF，之后可以恢复。

插件还可以读取书籍的版权页，把识别到的标题、作者、卷次、总卷数、版次、出版年、出版社和地点补到 Zotero 文献条目中。写入前会显示识别结果，已有字段不会被覆盖。

0.1.10 的“引用文本整理”可以把新高亮的误换行、多余空格和标点整理后直接保存到注释，也能按需处理选中的已有高亮。它适用于任何能选中文字、创建高亮的 PDF，不限 PaddleOCR 文件，不需要 Python 或 OCR API。保存的注释可按 Zotero 文库设置同步；PDF、MD/JSON 原文件不变。PDF 生成、识别和恢复等原有功能仍需要下面介绍的 Python 环境。

## 为什么还要安装 Python

Python 是插件的本机处理工具，负责读取 PDF、写入文字层、检查结果、备份和恢复文件。你不需要学习 Python，也不需要自己运行程序。

插件不会在电脑上安装 PaddleOCR 模型。需要新识别时，OCR 仍由 PaddleOCR 官方云端完成；Python 只负责上传、接收结果和处理 PDF。

插件需要：

- 64 位 Python 3.10 或更高版本；
- 推荐 Python 3.12，这是当前 Windows 实测使用的版本；
- 第一次处理 PDF 时能够访问 Python 包下载服务。

## 一、Windows x64：安装 Python

下面的方法适合普通用户，也适用于 Windows 10 和 Windows 11。

### 方法 A：使用 Python 官方安装管理器

1. 打开 [Python Windows 下载页](https://www.python.org/downloads/windows/)。
2. 下载页面顶部的 **Python install manager**，双击安装。
3. 安装完成后，关闭再重新打开 PowerShell。
4. 在 PowerShell 中运行：

```powershell
py install 3.12
```

5. 安装结束后，运行下面两条命令检查：

```powershell
py -V:3.12 --version
py -V:3.12 -c "import sys, struct; print(sys.executable); print(str(struct.calcsize('P') * 8) + '-bit')"
```

正常情况下会显示 Python 3.12、Python 程序的完整路径以及 `64-bit`。请记下第二条命令显示的路径；插件自动查找失败时会用到。

### 方法 B：使用传统 64 位安装包

如果你的电脑不能安装 Python install manager，可以在同一个下载页选择 **Windows installer (64-bit)**。不要选择 32 位版或 embeddable package。

运行安装程序时保留 `pip` 和 `venv`，并允许安装程序把 Python 加入当前用户环境。安装完成后，重新打开 PowerShell 并运行：

```powershell
python --version
python -c "import sys, struct; print(sys.executable); print(str(struct.calcsize('P') * 8) + '-bit')"
```

版本必须不低于 3.10，位数必须是 `64-bit`。

## 二、macOS：安装 Python

### 方法 A：使用 python.org 安装包（适合普通用户）

1. 打开 [Python macOS 下载页](https://www.python.org/downloads/macos/)。
2. 选择 Python 3.12 或更新的稳定版本，下载 **macOS 64-bit universal2 installer**。
3. 双击下载的 `.pkg` 文件，按提示完成标准安装。这个安装包同时支持 Apple Silicon 和 Intel Mac。
4. 安装完成后，打开“应用程序”中的 `Python 3.x` 文件夹，双击 `Install Certificates.command`。看到证书安装成功后关闭终端窗口。
5. 打开“终端”，运行：

```bash
python3 --version
python3 -c 'import sys, struct; print(sys.executable); print(str(struct.calcsize("P") * 8) + "-bit")'
```

正常情况下会显示 Python 3.12 或更高版本、完整路径以及 `64-bit`。

如果显示的路径是 `/usr/bin/python3`，并且版本低于 3.10，这是 macOS 自带的系统 Python，不要删除它，也不要把它填给插件。python.org 安装版通常位于：

```text
/Library/Frameworks/Python.framework/Versions/Current/bin/python3
```

### 方法 B：使用 Homebrew（已经安装 Homebrew 的用户）

```bash
brew install python
python3 --version
which python3
```

常见路径：

```text
Apple Silicon: /opt/homebrew/bin/python3
Intel Mac:     /usr/local/bin/python3
```

不熟悉 Homebrew 时，直接使用方法 A 即可。

## 三、安装 Zotero 插件

Windows 和 macOS 使用同一个 `.xpi` 安装包。

1. 打开 Zotero。
2. 进入“工具 → 插件”。
3. 点击右上角齿轮，选择“从文件安装插件”。
4. 选择 `pdf-helper-0.1.13.xpi`。
5. 按提示安装并重启 Zotero。
6. 打开 Zotero 设置中的 **PDF OCR Helper**。

![下载、从文件安装和设置的操作示意](images/installation.png)

进入“高级与维护 → Python 环境”，“Python 程序位置”先留空。插件第一次处理 PDF 时会自动查找 Python。

![Python 环境设置的离线界面示例](images/python-settings.png)

如果提示找不到 Python：

- Windows：填写前面检查命令显示的 `python.exe` 完整路径；
- macOS：填写 `python3` 的完整路径；
- 不要填写文件夹，也不要填写 macOS 的 `Python Launcher.app`。

点击“保存 OCR / PDF 设置”后，再重新执行一次操作。

### 设置在哪里找

新版使用两级导航。宽窗口在左侧选择大类和子页面；窄窗口将分类排在上方。每个大类可以折叠。

| 大类 | 子页面与用途 |
| --- | --- |
| 阅读与引用 | 高亮与复制：开启自动整理、选预设和标点；效果预览：先试一小段文字 |
| OCR 与 PDF | 账号与模型：填写令牌；识别速度与提醒：调并行数和本地页数提醒；文件保存与备份：设置 PDF 替换、备份和 MD/JSON 位置 |
| 高级与维护 | Python 环境：自动查找失败时填路径；旧版识别结果：处理缺页面尺寸的旧 JSON；任务与清理：查看进度、清理派生缓存 |

“保存引用整理设置”只保存阅读与引用，不启动 OCR。“保存 OCR / PDF 设置”保存其余页面的设置，不提交新任务。切换子页面不会丢掉未保存的输入；关闭设置窗口前仍需保存。遇到输入错误，面板会打开对应页面并提示。

普通用户通常只需填写访问令牌，其他值先保持默认。Python 路径通常留空；旧 JSON 坐标倍率不确定时保持 0。页数提醒只是本插件的本地记录，不代表账户剩余额度。

## 四、第一次使用会发生什么

第一次处理 PDF 时，插件会在 Zotero 配置目录中建立自己的 Python 环境，并安装两个组件：

- PyMuPDF：读写 PDF；
- HTTPX：连接 PaddleOCR 官方服务。

这一步可能需要几分钟。它不会修改系统 Python 中已经安装的包，也不会下载本地 OCR 模型。准备完成后，以后的任务会直接复用这个环境。

如果长时间没有进展，先不要反复点击 OCR。打开任务窗口查看提示，或检查 Zotero 配置目录下的：

```text
paddleocr-pdf-repair/setup.log
```

日志不会记录 Access Token。

## 五、先做一次不消耗额度的测试

建议先用一份可以丢弃的小型扫描 PDF，以及与它匹配的 MD 和 JSON：

1. 把 PDF、MD 和 JSON 放在同一个 Zotero 文献条目下；文件名尽量相同，例如 `paper.pdf`、`paper.md`、`paper.json`。
2. 右键 PDF，选择“合并已有 MD/JSON，生成可检索 PDF”。
3. 等待任务窗口显示“已完成”。
4. 打开 PDF，搜索一个确定存在的词，检查页数和页面外观。
5. 右键 PDF，选择“恢复原始 PDF”，确认恢复功能正常。

这条测试路径不需要 Access Token，也不会提交云端 OCR。

## 六、两种常用方式

### 已经有 MD 和 JSON

右键 PDF，选择“合并已有 MD/JSON，生成可检索 PDF”。

JSON 必须包含每段文字的位置。只有 MD、或者 JSON 中没有坐标时，插件无法把文字放回正确的位置。如果同一条目中有多组文件，插件会让你手工选择。

### 需要重新 OCR

1. 在插件设置中保存 AI Studio Access Token。
2. 右键 PDF，选择“PaddleOCR 识别并替换为可检索 PDF”。
3. 插件先提交云端任务，取得 MD 和 JSON 后，再在本机生成 PDF 文字层。

提交成功后不要因为等待时间长而重新创建任务。可以在任务窗口恢复或继续原任务，避免重复上传和重复计入额度。

## 七、从版权页补全文献条目

这项功能适合书籍扫描件。PDF 需要已经有可读取的文字层，或者已经有对应的 OCR JSON。

1. 在 Zotero 中只选中一个 PDF 附件。
2. 右键选择“识别版权页并补全文献条目”。
3. 插件在本机检查 PDF 前 40 页，并显示疑似版权页的页码和识别结果。
4. 核对标题、作者、卷次、总卷数、版次、出版年、出版社和地点。
5. 确认后，插件把缺少的内容写入 PDF 所属的父文献条目。

已有字段不会被覆盖。例如条目已经有标题和作者，插件会保留原内容，只补出版社和地点等空字段。取消确认不会修改条目。

版权页识别本身不会提交云端 OCR。扫描 PDF 如果还没有文字层或 OCR JSON，请先完成一次 OCR，或先合并已有 MD/JSON。插件找不到可信版权页时也不会猜测写入。

“版次”和“出版年”会分开处理。例如版权页写有“2012 年 3 月第 1 版”，Zotero 的“版次”填“第1版”，“日期”填“2012”。卷次会写入“卷”，总卷数会写入“卷数”。

## 八、MD/JSON 保存在哪里

普通用户建议选择“独立存档条目”。插件会建立“PDF Repair 识别存档”集合，把 MD 和 JSON 放在专门的资料条目中，并关联原文献。只要启用了 Zotero 文件同步，这些文件就可以同步到其他设备。

其他选项：

| 选项 | 适合情况 |
| --- | --- |
| 独立存档条目 | 推荐；原文献附件列表更整洁，并可随 Zotero 同步 |
| 插件本地隐藏目录 | 只在当前电脑使用，不需要跨设备同步 |
| 原文献下的独立附件 | 希望 MD/JSON 与 PDF 显示在一起 |
| 原文献下的链接附件 | 文件放在自己管理的目录中；Zotero 不同步文件 |

任务历史、Python 环境和 PDF 恢复备份保存在每台电脑本地，不会通过 Zotero 同步。

## 九、任务状态怎么看

- “上传中”：正在发送当前段，并等待服务端确认。
- “云端排队中”：服务器已接收，正在等待处理。
- “云端解析中”：服务器正在识别。返回页数时会显示“已解析多少页”和百分比；没返回时会明确提示“云端未返回页数”。
- “下载识别结果”：云端识别已完成，正在取回 JSON。此时识别进度即使到 100%，PDF 也还需要本机生成和保存。
- “生成中”：正在把文字写入 PDF。
- “等待保存”：结果已经生成，正在备份或替换文件。
- “已完成”：PDF 已替换并完成收尾。
- “已生成，未替换”：关闭了自动替换，结果仍在任务目录。
- “索引待重建”：PDF 已保存，但 Zotero 全文索引需要稍后重建。
- “暂停”或“失败”：打开任务详情查看原因，不要直接重新提交 OCR。

任务窗口上方显示整份文件的已解析页数和已下载结果页数，下方逐段列出页码范围、状态和最近查询时间。只要最近查询时间持续更新，就说明插件仍在连接云端；云端排队或未返回页数时，百分比可能暂时不变。

文件超过 50 MB 或 1,000 页时会自动分段。新版尽量把每段装到接近 48 MB，同时识别两段；结果仍按原页码合并。设置里“同时处理几份 PDF”控制不同文件，“同一 PDF 同时识别几段”控制单个大文件。普通用户保持默认的 1 份 PDF、2 段即可。网络不稳定或频繁限流时，可将同时识别段数改为 1。

上传、排队、解析、下载的耗时分别列出。这些是插件观察到的累计时间，可能有几秒误差；并行时两段的时间会重叠。升级前的任务未记录过的阶段显示“此前未记录”，不会猜测补齐。云端繁忙时，并行也不能保证固定提速倍数。

### 从 0.1.6 / 0.1.7 / 0.1.8 升级

用新版 XPI 覆盖安装后完全退出 Zotero，再重新打开。原有设置、Python 环境、任务和识别结果保留；无需重新填写 Token 或重装 Python。

原来运行中的任务会继续查询已保存的云端任务编号，并复用已下载结果。已经拆成四段的任务会沿用原四段，后续未完成段可并行；新的分段方式只用于还没有分段记录的新任务。遇到“暂停”，点一次“恢复 / 重试”。不要删除记录或另建重复 OCR 任务。

## 十、常见问题

### 怎样让新高亮直接保存整理好的文字

1. 打开设置 → PDF OCR Helper → 阅读与引用 → 高亮与复制。
2. 勾选“开启引用文本整理”和“新建高亮时自动整理并保存文字”。
3. 选择“论文引用（推荐）”，再点击“保存引用整理设置”。
4. 回到 PDF 新建一条高亮。Zotero 保存新高亮后，插件按当前规则整理并保存摘录，侧边栏使用原生注释显示；可能有 Zotero 正常保存所需的短暂等待。

这会实际改变新注释，不是显示覆盖层，也不保留修改前摘录的副本。编辑、复制注释和拖入笔记时，用的都是实际保存值。关闭开关只停止后续整理，不会还原已保存内容；不要把关闭开关或 Zotero 撤销当作恢复原文的保证。PDF 和 OCR 文件始终未改动，必要时可重新选择 PDF 原文。

本版只自动处理之后在 Zotero 阅读器中新建的可编辑高亮/下划线；旧注释、同步或导入的注释、只读注释以及手工编辑后的修改不自动重写。设置页保存规则不会批量处理历史高亮。已有高亮可用下面的手动选项处理。

任何可以选择文字并创建高亮的 PDF 都适用，不需要经过 PaddleOCR。没有文字层、不能选择文字的扫描件仍需先 OCR。仅选择但不创建高亮不会修改 PDF，可使用选择工具条的复制动作。

### 怎样整理已经存在的高亮

1. 在“高亮与复制”中开启“引用文本整理”，选好规则并保存。
2. 回到 PDF，在阅读器侧边栏选中要处理的一条或多条高亮/下划线。
3. 右键选择“整理并保存选中高亮文字…”。
4. 看清确认框中的数量后继续。插件只处理这些选中项，完成后显示已保存、无需修改、跳过和失败的数量。

这个动作会实际保存注释摘录，不保留旧文字副本；评论、标签、颜色、页码、位置和 PDF 不改动。取消确认不会保存。外部或只读注释不能处理，不会自动扫描整篇 PDF 或整个文库。

不想自动整理新高亮时，可以关闭“新建高亮时自动整理并保存文字”，保留总开关，用右键按需处理。升级不会自动修复旧高亮；想应用新规则的旧高亮需要手动选中处理。

### 高亮里为什么还有空格

0.1.10 补齐了中文引号前后的空格和 PDF 常见的特殊空格。例如：`制造 “碎片化” 与 “整体化”` → `制造“碎片化”与“整体化”`；`理论批 评` → `理论批评`。英文单词之间必要的空格保留。

确认“去掉中文之间的多余空格”和“清理标点旁的多余空格”已开启并保存。新规则不会自动重写旧高亮，请使用上面的手动动作。如果直接从 PDF 页面选中文字并复制，得到的仍可能是 PDF 原始文字；保存后的注释与 PDF 文字层是两回事。需要整理后的复制结果，可以用插件的“复制为论文引用文本”。

### 怎样复制适合论文引用的文字

选中 PDF 文字，在弹出工具条中点“复制为论文引用文本”；原样复制则点“复制原始文字”。也可右键侧边栏的一条或多条高亮，选“复制为论文引用文本”或“复制当前注释文字”。后者复制的是当前保存值，不能恢复修改前摘录。普通便签没有摘录时，复制动作使用评论；有摘录时不混入评论。

已经在其他地方复制的文字，可以从 Zotero 的“工具 → 引用文本整理：粘贴并复制”打开小窗口处理。设置页底部也有原文与整理后预览，可以先试一小段，预览文字不会保存。

Zotero 自带的复制、拖动高亮到笔记和批注导出仍由 Zotero 负责；保存后的注释文字已整理，不需要另一层显示转换。直接从 PDF 选中文字得到的原文仍来自 PDF。插件的专门复制动作不自动附带出处或页码。

### 整理方式和标点怎么选

“论文引用”自动整理标点、误换行和空格，适合中文论文；“轻度整理”主要处理换行和空格，尽量不改标点。手动修改任一详细规则后会显示“自定义”。

| 标点格式 | 适合情况 |
| --- | --- |
| 自动判断（推荐） | 中文附近用中文标点，纯英文段落保留英文标点 |
| 统一为中文标点 | 整理中文正文；明显英文引文、网址等保留 |
| 统一为英文标点 | 将正文中的中文标点转为英文半角标点 |
| 保持原文 | 不转换标点，仍按勾选项整理换行和空格 |

网址、DOI、邮箱、小数、版本号等会自动保护，不需要另设开关。“在中文和英文之间自动加空格”和“尝试清理 OCR 异常字符”默认关闭；特殊史料、旧式排版或诗歌引用建议用轻度整理或复制原文，并逐句核对。程序不能判断所有真实段落或断词，也不会修正 OCR 识别错字。

### 插件提示“找不到 Python”

先运行前面的检查命令。如果命令正常，把它显示的完整 Python 路径复制到插件设置中。路径末尾应当是 Windows 的 `python.exe` 或 macOS 的 `python3`。

### 首次准备失败

常见原因是网络无法访问 Python 包下载服务，或者安全软件阻止 Python 建立环境。检查 `setup.log`。网络恢复后重新执行原操作即可，不会因此调用 OCR。

### 提示 MD/JSON 尚未下载

先在 Zotero 中下载对应附件。插件不会因为同步文件缺失而自动重新 OCR。

### 版权页没有识别出来

插件只检查前 40 页，并要求页面中出现 CIP、ISBN、出版社、版次等较明确的标记。先确认 PDF 可以复制文字；如果不能，请先完成 OCR。版权页版式过于特殊或识别文字错误较多时，插件会停止，不会把不确定内容写入条目。

### 提示 JSON 没有 `width/height`

这是旧识别结果缺少页面尺寸，不是 PDF 损坏。只有在你明确知道旧结果使用的 PDF 渲染倍率时，才能在设置中填写倍率；不确定时保持 `0`，不要猜。

### PDF 没有被替换

常见原因包括：PDF 正被其他程序占用、文件在任务期间被修改、JSON 页数或坐标不正确、文献库不允许修改文件，或者关闭了自动替换。关闭其他 PDF 阅读器后，可以在任务窗口重试保存。

### 是否需要一直保留 Python

如果要生成、检查或恢复 PDF，仍然需要 Python。你不需要手工启动它；插件会按需启动后台服务，空闲后自动退出。只使用引用文本整理不需要 Python，但不会因此获得扫描 PDF 的文字：没有文字层时仍需先做 OCR。

### 卸载插件会删除 PDF 或备份吗

不会。卸载插件不会自动删除任务、备份、MD/JSON 或插件专用 Python 环境。确认不再需要恢复后，再手工清理 Zotero 配置目录中的 `paddleocr-pdf-repair` 文件夹。

## 十一、安全提醒

- Access Token 保存在 Zotero/Firefox 登录管理器中，不写入任务日志。
- 插件只在本机 `127.0.0.1` 上启动带随机凭证的后台服务。
- 插件替换 PDF 前会校验文件并保存原始备份。
- 已提交到云端的任务不能通过“取消”退回额度。
- 首次使用真实文献前，建议先完成一次小文件的离线合并和恢复测试。
